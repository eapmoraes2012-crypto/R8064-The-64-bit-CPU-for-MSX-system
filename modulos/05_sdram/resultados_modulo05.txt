MODULE 05 - Embedded SDRAM controller (Tang Nano 20K) for 64-bit R8064 accesses - simulation 2026-11-02
ASSUMPTIONS (NOT CONFIRMED ON THE CHIP): geometry 4 banks x 2048 rows x 256 columns x 32 bits (64 Mbit; 11 row bits, 8 column bits, A10 = precharge); CL=2; BL=2 (64 bits = 2 words);
  generic SDR timings at 100 MHz: tRCD=2, tRP=2, tRAS=5, tRC=7, tRFC=7, tWR=2, tMRD=2 clocks; refresh every 7 us (700 clocks; covers 8192 rows in 64 ms); 200 us init. Everything is a parameter.
  The testbench's SDRAM model was written by me from these assumptions (it is not the manufacturer's model) - it verifies the protocol, it does not prove compatibility with the chip.
WHAT WAS SIMULATED (Icarus Verilog 14.0): 71,434 accesses (64-bit writes with byte-enable and reads): sequential 8192 words, byte-enable, row conflict in bank 0,
  4 interleaved banks, 30,000 random accesses in 4 MB (70% read), 40 us idle, 20,000 random verification reads. Shadow memory: 0 data divergences.
  SDRAM model with checker (tRCD, tRP, tRAS, tRC, tRFC, tWR, tMRD, ACT on active bank, READ/WRITE without a row, DQ contention, MRS/refresh at initialization, interval between refreshes): 0 violations.
  Initialization: PRECHARGE ALL, 2 AUTO REFRESH, LOAD MODE (BL=2, CL=2); periodic refreshes: 837 in the test, longest interval 708 clocks (limit 800).
LATENCY (clocks from the clock in which the request is accepted to rvalid/wdone; 1 request at a time):
  open page: read 5, write 1 (posted) | closed bank: read 7, write 3 | other row (conflict): read 9, write 5
  Access delayed by refresh: up to 13 clocks. Refresh cost: about 1.5% of the time (11 clocks every 700).
  COMPARISON WITH THE SPREADSHEET: W_RD_HIT=4 (read access = 1 + 4 = 5 clocks) matches the open-page read EXACTLY. W_WR_HIT=2 (3 clocks) is conservative: the posted write takes 1.
  The spreadsheet has no parameters for a page miss: this controller adds +2 (closed bank) or +4 (conflict) wait clocks on reads (writes: +2 or +4).
  Sequential read throughput on an open page: 8 bytes / 5 clocks = 160 MB/s at 100 MHz (one request at a time; a controller with overlapped reads would reach ~2 clocks per 64-bit access).
SYNTHESIS / P&R (Yosys 0.70 + nextpnr-himbaechel, GW2AR-LV18QN88C8/I7, 100 MHz, with LFSR wrapper): version 1 (indexed arrays): 92 MHz -> FAILED (hit decision + timer readiness
  in the acceptance clock, RAM16SDP4 distributed memory). Final version (packed vectors, one-hot, same function and same cycles): 109.7 MHz PASS.
  Isolated controller (Yosys): 224 LUT4 + 128 ALU + ~420 MUX2 (data and state muxes), ~440 FF, 0 BSRAM.
MUTANTS: 8 deliberate changes in the RTL (smaller tRCD, tRP, tRFC, swapped DQM, write DQM removed, PRECHARGE omitted, READ/WRITE without waiting tRCD, slow refresh) - all detected.
  Changes in tRAS/tWR and ok_pre=1 do NOT change the result: with one request at a time the flow already respects these times at the exact limit (confirmed: with tRAS=6 or tWR=3 in the model there are violations).
  A real defect was found and fixed: the refresh counter had 10 bits and did not refresh with REF_INT > 1023 (the test only caught it after adding the "late refresh" check to the model).
NOT COVERED: real signals of the GW2AR-18 embedded SDRAM (Gowin primitives/IO, SDRAM clock phase from the PLL, I/O delays), timing with the chip's real times, manufacturer's model,
  several requests in flight, F2/M arbitration, integration with the pipeline, 8 MB memory area (only 4 MB used by the R8064), power consumption.
