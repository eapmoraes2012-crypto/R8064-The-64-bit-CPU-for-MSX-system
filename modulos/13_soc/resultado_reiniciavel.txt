REV22 - restartable PUSH, CALL and interrupt entry after a data fault (Icarus Verilog 14 simulation, full SoC: core + MMU + caches + SDRAM)

Change: the PUSH/CALL/INT entry (IM1/IM2) write uop addresses [SP-2] with a constant immediate (uop bit 79, 'immc' = -(1<<isz)) and SP is only updated
afterwards (SP := SP + immc). Before: DEC SP, DEC SP, write; a fault left SP already decremented and the restart decremented again.
IM2: the vector [I:FF] is read into TMP before pushing. Fault during INT entry: IFF2 := 1 and irq_pend := 1 (RETN re-enables and the INT is accepted again).
LDIR/LDDR/CPIR/CPDR/OTIR/OTDR, POP and RET were already restartable (the access is the first uop with a visible effect; TMP is not visible); now there is a test. INI/INIR/IND/INDR are NOT (the port read has already happened).

New tests in 13_soc/sim/tb_soc_exc.v (+sc=N); page 1000h-1FFFh starts unmapped, the testbench maps it on the first fault and the handler returns to the instruction:
  +sc=4  PUSH BC / POP DE with the stack at 1FFEh        -> final SP 2000h, DE=BC
  +sc=5  CALL 0030h with the stack at 1FFEh              -> final SP 2000h, returns to CALL+3
  +sc=6  LDIR with a read at 1000h on the 3rd byte (HL=0FFEh, BC=4)   -> correct copy, HL=1002h, 1 fault
  +sc=7  LDIR with a write at 1000h on the 3rd byte (DE=0FFEh, BC=4)   -> correct copy, HL=0104h, 1 fault
  +sc=8  EI with INT active and IM1; the entry pushes at 1FFEh (fault) -> the INT handler runs after the restart, pushed PC correct
Result with the PREVIOUS RTL: sc=4 ERROR (SP=1FFEh, double decrement), sc=5 ERROR (SP=1FFEh), sc=8 ERROR (SP=1FFEh after the POP); sc=6 and sc=7 OK.
Result with the NEW RTL: sc=1..8 all OK, 0 SDRAM violations.

Regression (same testbenches, previous x new RTL, mems regenerated with each one's gen_roms): tb_cpu_gov (4 modes), tb_sys, tb_sys_seq, tb_sys_ldir, tb_sys_irq (Z80 and R800),
tb_xing, tb_exini, tb_blk, tb_io, tb_irq, tb_irq2 (IM1 and IM2), tb_irq3, tb_ldai, tb_seq, tb_soc and tb_soc +mmu: all OK on both; identical outputs (the governed times do not change),
the only textual difference: the PC printed at the end of tb_seq (8 -> A), because PUSH/CALL in native mode now use 2 and 3 uops instead of 3 and 4 (4 clocks less each).
Yosys synthesis (synth_gowin, pnr_gov_top): 3276 LUT4 (before 3355 in the yosys.log of the last run), 700 ALU, 18 SPX9. Fmax NOT re-measured: run 10_mode_gov/pnr/rodar_pnr.bat (86 MHz, 3 seeds);
the only new path is the immediate mux (imm_xr <= u[63] ? 0 : u[79] ? constant : immv).
Files changed: r8064_core_min.v (09_core_min and 10_mode_gov), gen_roms.py and uop.mem (09_core_min, 10_mode_gov, 13_soc, pnr), tb_soc_exc.v, rodar_exc.bat, LEIA-ME.txt. Previous copies in bak/antes_reiniciavel.
