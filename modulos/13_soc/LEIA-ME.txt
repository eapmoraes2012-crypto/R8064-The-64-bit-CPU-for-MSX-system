Module 13 - SoC: MSX system (core+mode+governor+msx_mem+FIFOs) + MMU (TLB I=4, D=8) + 4 KB I cache + 8 KB D cache + 4-master arbiter (registered request) + SDRAM controller.
Files: rtl/r8064_soc.v (top), rtl/r8064_memsys.v (memory subsystem), rtl/mem_arb5.v (5 masters), r8064_dma.v, r8064_xbuf.v, cache_dm.v, mmu.v, sdram_ctrl.v. The others (core etc.) are in 09_core_min/rtl and 10_mode_gov/rtl.
Test: sim/tb_soc.v (SDRAM model with protocol checking): sequence program executed from the SDRAM. No argument: MMU in bypass. +mmu: MMU on with Sv39 tables in the SDRAM
(VA 0000h-0FFFh and 4000h-4FFFh mapped 1:1); checks 6 table reads in the I-MMU and 3 in the D-MMU. Result: SOC OK, 0 SDRAM violations.
Compile: iverilog -g2012 -o soc.vvp sim/tb_soc.v rtl/*.v sim/sdram_model.v <all the core .v files>   (also copy gov_rom.mem, uop.mem, mainctrl.mem, amb_idx.mem, ctrl_b.mem, rom_ed_*.mem to the run folder)
Translation faults -> EXCEPTION IN THE CORE (rev20): the adapter generates i_fault/d_fault pulses (aligned to the ack, data 0, write discarded) + cause (1 page, 2 permission, 3 A/D, 4 bus).
  - DATA fault: kills the instruction in M (no write to the register file), flushes the pipeline and jumps to the vector (CR9 = 'vec', default 0040h). EPC = PC of the instruction (restarts whole).
  - FETCH fault: taken at the instruction boundary when the candidate is <= 12 bytes from the faulting word (EPC = PC of the candidate; address = word, aligned to 8).
  - Registers (CR n = MFCR/MTCR n; bank index 32+n): CR11 cause {write[4], data[3], cause[2:0]}, CR12 fault address, CR13 EPC (read-only, written by the hardware),
    CR14 MMU {ASID[15:8], user[1], en[0]}, CR15 root PPN, CR16 (write) TLB flush by VA, CR17 (write) b0 full flush | b1 by ASID (AX[15:8]) | b2 invalidates caches.
  - Instructions: ED 0A n = MFCR n (AX := CR[n]) ; ED 0C n = MTCR n (CR[n] := AX).  Entering the exception does IFF2 := IFF1 and IFF1 := 0 (RETN restores).
  - RESTARTABLE (rev22): PUSH, CALL, interrupt entry (IM 1 and IM 2), POP, RET, LDIR/LDDR/CPIR/CPDR and OTIR/OTDR. The PUSH/CALL/INT write goes to [SP-2] BEFORE SP is updated (constant immediate, uop bit 79), so a fault leaves SP intact and the whole instruction is re-executed. In LDIR and the like the access comes before HL/DE/BC change and TMP is not visible.
  - LIMITATION: INI/INIR/IND/INDR are not restartable (the port read has already happened when the write to [HL] faults). A fetch fault near the end of a page may be taken up to 12 bytes before use (prefetch). Fault on INT entry: IFF2 := 1 and the INT is requested again (RETN re-enables).
  - Adapter fix: with a fault/posted-write ack the core still held the request and it was accepted again (duplicate access); now !ack_r. A fetch withdrawn by the core (flush) has its in-flight response discarded (i_cancel).
Test: sim/tb_soc_exc.v with +sc=1 (read on an unmapped page; the testbench maps the page; the handler returns to the POP and ends with BC=1234h), +sc=2 (PUSH on an unmapped page), +sc=3 (CALL to an unmapped page: fetch fault), +sc=4 (PUSH on the unmapped stack, restarts and checks SP), +sc=5 (CALL with the unmapped stack), +sc=6 (LDIR with a read fault on the 3rd byte), +sc=7 (LDIR with a write fault on the 3rd byte), +sc=8 (fault while pushing the PC on INT IM1 entry). The MMU control registers now come out of the core (CR14-17); r8064_soc no longer has the mmu_en/fl_* ports.
Synthesis (Yosys + nextpnr, Tang Nano 20K): pnr/ys_mem_top.ys and pnr_mem_top.v (isolated memory subsystem). Full SoC: pnr/rodar_pnr_soc.bat (Yosys + nextpnr, seeds 1-4, 57.28 MHz); board top: pnr/rodar_pnr_board.bat.
Resultados: ver 13_soc/resultado_soc.txt
CR NUMBERING: "CR n" (n = operand of MFCR/MTCR) is at bank index 32+n. The RTL, tb_soc_exc and resultado_soc.txt use the bank INDEX:
  CR41 = CR9 (vector), CR42 = CR10 (ie), CR43 = CR11 (cause), CR44 = CR12 (address), CR45 = CR13 (EPC), CR46..CR49 = CR14..CR17 (MMU, root, TLB-VA, control).
rodar_exc.bat runs tb_soc_exc (scenarios 1-8), tb_soc (bypass and +mmu) and tb_clkgen (-DSIM).
What the SoC does NOT instantiate: mul/div (03), msx_if (04; the MSX bridge used is r8064_fifo_if of module 10), FPU (08/11) and the classic Z80 (12).
