MODULE 14 - vec3d_unit (3D manipulation, measurement prototype) - 09/11/2026
=======================================================================
FORMAT: vector = 4 int16 lanes (x,y,z,w) in a 64-bit register; fixed point with output shift sh (0-31) and rounding to nearest.
OPERACOES (11): VMUL, VDOT4, VDOT3, VCROSS3, VADD, VSUB, VMIN, VMAX, VSHUF (swizzle por imm8), VNEG, VABS. VMUL/VCROSS3/VADD/VSUB/VNEG saturam em int16;
  VDOT4/VDOT3 return a 64-bit scalar (sum of 32-bit products, no overflow) shifted by sh. 1 operation per clock, latency 5.
VERIFIED (simulation, Icarus): 30,000 random+corner vectors (op, sh 0-16, imm), Python integer reference model (seed 8064), 0 errors, outputs 1 per clock.
MEASURED (Yosys synth_gowin, isolated unit):
  completa (LANE_ALU=1): 863 LUT4 + 452 ALU (= 1.315 LUT4 eq.), 935 FF, 6 MULT18X18, 0 BSRAM
  minimal   (LANE_ALU=0, without VADD/VSUB/VMIN/VMAX/VNEG/VABS): 762 LUT4 + 309 ALU (= 1.071), 855 FF, 6 MULT18X18
MEASURED (nextpnr-himbaechel, GW2AR-LV18QN88C8/I7, LFSR wrapper, target 100 MHz): 100.75 / 88.61 MHz (seeds 1/2) -> PASSES at 57.28 MHz with margin.
  History: v1 (separate adders and comparators per op, saturation by comparator) 4,436 LUT4 + 922 ALU; v2/v3 (shared adder, saturation by sign extension) 894+442 at 67 MHz (FAILS 100);
  final version (S4 split into shift | add+saturation): 863+452 at 89-101 MHz. Old versions in rtl/*_v?.v.
NOT DONE: integration into the core (decoding, reading 2 64-bit registers, writing, hazards, exception precision), reciprocal/reciprocal square root (rsqrt) by table in BSRAM,
  microcoded MATVEC4 with an internal accumulator, 32-bit lanes (Q16.16), PnR inside the SoC.
BUDGET IMPACT (rev20: total 16,330 LUT4 eq. = 78.8 %; target 85 % = 17,600; margin 1,270): +1,315 -> 17,645 (85.1 %) ; minimal version +1,071 -> 17,401 (83.9 %). Row 11 of the spreadsheet
  (Multimedia level 1: SIMD, 4x16 mult, recip/rsqrt, ~960 LUT4, postponed) and is replaced by this unit (+ ~100-150 LUT4 and 1-2 BSRAM for the rsqrt). DSP: 6 of 48 (mul/div uses 4: 38 left).
  The SoC measured today (board top: 10,982 LUT4 + 1,064 ALU = 12,046 = 58 %) does not yet include mul/div, the residual FPU or peripherals.


===== REVISION 10/11/2026: AREA MEASUREMENT CORRECTION + INTEGRATION + OPTIMIZATION =====
ERROR IN THE PREVIOUS MEASUREMENT: above, "LUT4" was only the Yosys LUT4 cell. nextpnr counts as LUT4 ALL the LUTs (LUT1+LUT2+LUT3+LUT4) and the MUX2_LUT5..8; the ALU is separate.
Correct measurement of v5 (complete): LUT1-4 2,064 + MUX2_LUT 311 + ALU 452 = ~2,830 LUT4-eq (nextpnr, with the test wrapper: LUT4 2,638 + ALU 512).
  (the "1,315" and "1,071" given before were WRONG by underestimating ~2x; the minimal version too.)
INTEGRATED into the core (see ISA_3D.txt): uop[80]=vec (81-bit uop, still 9 BSRAM), ED F8/FA/FB (ids 294-296), old regression identical (21 tests), SoC and exceptions OK,
  tb_vec (09_core_min/sim): random programs of ~3,000 3D operations with/without bank prefixes, 0 errors.
OPTIMIZED (v6, no loss of function; verified with the same 30,000 vectors): 
  (1) VNEG/VABS now use the multipliers (a*-1, a*sign(a)) - the operand swap of the lane adder disappears;
  (2) VCROSS3 with 6 dedicated multipliers (10 DSP in total): the DSP input multiplexer disappears;
  (3) DOT3 zeroes the w lane at the multiplier input (one sum tree instead of two); (4) 4-bit sh (ISA: 0..15), exact widths (34/33 bits),
  (5) inputs directly into the DSPs (latency 5 -> 4, 128 FF fewer).
  Result: Yosys LUT1-4 1,659 + MUX2 267 + ALU 409 = ~2,335 LUT4-eq (-17%); isolated nextpnr 2,080 LUT4 + 466 ALU (-19% vs 3,150), 10 DSP, Fmax 114.9 MHz (target 70).
  Variant without VADD/VSUB/VMIN/VMAX (LANE_ALU=0): -250 LUT4-eq (not adopted: loses function).
  In the SoC (board top, random ROMs, Yosys): +1,419 LUT(1-4+MUX2) +441 ALU = ~+1,860 LUT4-eq, +10 DSP, BSRAM the same (reference without the unit: 11,807 LUT + 919 ALU).
CUSTO POR FUNCAO na v6 (experimentos de eliminacao, LUT4-eq): deslocador+arredondamento 676 | VSHUF 228 | VDOT 237 | VCROSS3 166 | VADD/VSUB 174 | VMIN/VMAX 109.
TRIED AND DISCARDED: v7 (16-bit window shifter + thermometer saturation test on lanes 1-3): +120..+180 (ABC already optimizes the naive version better).
NOT DONE (ideas with estimates, not measured): DOT/CROSS in the MULTADDALU18X18 blocks of the DSP (~-200 ALU, requires Gowin primitives + simulation model);
  multicycle unit (1-2 lanes/clock: ~-180..-300 LUT4-eq, throughput 1 op per 2-4 clocks; the current front-end only issues 1 instruction every >=6 clocks).
BUDGET: rev20 16,330 (78.8 %) + ~1,860..2,335 = ~18,200..18,700 (87.7..90 %) - ABOVE the 85 % target (17,600). Measured on the board top (nextpnr, without the unit): 12,046 (58 %).
FMAX RISK: the core's 'hold' gained the term (vec_m && !vo_valid); it needs PnR of the board top (rodar_pnr_board.bat, 4 seeds) to confirm 57.28 MHz.
